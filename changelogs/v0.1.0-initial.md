# v0.1.0 — Initial Implementation

**Status**: Foundation complete  
**Date**: Pre-stabilization

---

## What Was Built

The initial implementation of a custom multi-tenant identity and authorization server in Go.

### Core Architecture

Clean architecture (ports and adapters) with explicit layering per domain:

```
domain/    → entities + repository interfaces
app/       → use cases (business logic)
infra/     → postgres adapter implementations
transport/ → HTTP handlers
middleware/→ request-level concerns
```

### Domains Implemented

#### Identity
- `identities` table — global, email-unique human identities
- `users` table — tenant-scoped memberships (identity + tenant, unique pair)
- CreateIdentity, GetUser, ListUsers, CreateUser use cases

#### Authentication
- `POST /register` — creates identity + credential + tenant + user + owner role atomically in a transaction
- `POST /login` — validates email/password (Argon2id), creates session, returns session ID + opaque refresh token
- `POST /refresh` — rotates refresh token; revokes old session, creates new with `parent_session_id` chain

#### Session Management
- Sessions stored in postgres with SHA-256 hash of refresh token (raw token never persisted)
- `ExpiresAt` (24-hour TTL) and `RevokedAt` for revocation tracking
- `ParentSessionID` enables full rotation audit trail

#### Authorization (RBAC)
- Three-tier model: Users → Roles → Permissions
- Roles are tenant-scoped; permissions are globally named (`users:create`, `roles:read`, etc.)
- `tenant_owner` role bootstrapped on registration with a full permission set
- `POST /roles`, `GET /roles`, `POST /roles/{id}/permissions`, `GET /roles/{id}/permissions`

#### Tenancy
- Every user, role, and session is tenant-scoped
- Slug auto-generated from registering email's local part

### Infrastructure

- **PostgreSQL** via `pgx/v5` with connection pooling
- **Redis** client initialized (unused at this version)
- **NATS** client initialized (unused at this version)
- **chi** HTTP router
- **Transaction management** via context-injected `pgx.Tx`
- **Argon2id** password hashing (Memory: 64MB, Iterations: 3, Parallelism: 2)
- **Crypto-random** opaque refresh tokens (32 bytes, base64-URL encoded)

### Database Schema

Full schema covering: `tenants`, `identities`, `users`, `credentials`, `sessions`, `roles`, `permissions`, `user_roles`, `role_permissions`, `devices`, `mfa_factors`, `oauth_clients`, `service_accounts`, `audit_events`, `policies`.

Tables for OAuth, MFA, devices, service accounts, and audit events exist in schema but have no application code yet.
