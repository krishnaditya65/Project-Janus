# v0.8.0 — Scalability & Observability

Closes the JWT-vs-Session-ID gap, surfaces production telemetry, and adds the background workloads needed to keep the system healthy under sustained traffic.

## Changes

### Principal cache (Redis) — `internal/auth/middleware/principal_cache.go`
- Session-ID auth path now consults Redis (`auth:principal:<sid>`, 5-min TTL) before doing the 4-DB-read principal load.
- Hit/miss counters wired into Prometheus.
- Invalidated on `Logout` and on `Refresh` (which revokes the old session).
- **Effect**: Session-ID `/me` p50 went 14.1 ms → 1.5 ms (9× faster).

### Structured request logging — `internal/platform/httpserver/logging.go`
- Per-request `slog` line with method, path, status, duration (ms), bytes, remote IP, user-agent.
- Log level scales with status: 5xx → ERROR, 4xx → WARN, else INFO.

### Prometheus metrics — `internal/platform/metrics/metrics.go`
- New `GET /metrics` endpoint (Prometheus text format, Cache-Control via promhttp).
- Counters: `auth_http_requests_total{method,route,status}`, `auth_events_total{event}`, `auth_principal_cache_hits_total`, `auth_principal_cache_misses_total`.
- Histogram: `auth_http_request_duration_seconds{method,route,status}` with sensible buckets (1ms→10s).
- Route label uses chi's route template (`/users/{userID}`) — bounded cardinality.

### Async audit logging — `internal/audit/`
- `Publisher` fires JSON to NATS subject `audit.events` (best-effort; never blocks the auth path).
- `Consumer` runs in the `worker` binary, persists to `audit_events` table.
- Event constants in `domain/event.go`: login, login_failed, refresh, logout, mfa.*, oauth.*.

### Session cleanup worker — `cmd/worker/main.go`
- Ticker every 5 minutes deletes sessions whose `expires_at` or `revoked_at` is older than 30 days.
- Runs alongside the audit consumer in the same binary.

### Read replica routing — `internal/platform/postgres/pools.go`
- New `Pools{Writer, Reader}` type. Without configuration, both point at the same pool (backward compatible).
- New env var `DATABASE_READ_URL`; if set, a separate pool is created and exposed for read-only query paths.

## A/B re-validation

Before (v0.7.0): Session ID 15.15ms mean, JWT 4.16ms — JWT 3.6× faster.
After  (v0.8.0): Session ID **1.58ms** mean, JWT 2.32ms — Session ID 1.5× faster (cache hits in <1ms vs JWT crypto + signing-key DB lookup).

The next obvious win is in-process LRU for `signing_keys` so JWT verify also stops hitting the DB.
