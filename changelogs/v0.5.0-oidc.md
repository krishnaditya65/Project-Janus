# v0.5.0 — OIDC (OpenID Connect)

Adds OIDC ID tokens, discovery document, and the UserInfo endpoint on top of the existing OAuth flow. Any OIDC-compliant relying party (Next-Auth, Auth0 SDKs, Spring Security, etc.) can now integrate.

## New components

- `internal/oidc/app/id_token_service.go` — `IDTokenService.IssueIDToken(ctx, principal, clientID, nonce, ttl)`; reuses `tokenapp.JWTService`
- `internal/oidc/transport/http/discovery.go` — `GET /.well-known/openid-configuration`
- `internal/oidc/transport/http/userinfo.go` — `GET /oauth/userinfo` (Bearer-authenticated)

## Changed

- `internal/oauth/app/token.go` — when `openid` scope is requested, the `IDTokenIssuer` interface is invoked alongside the access token. ID token includes the `nonce` from the original authorize request, `aud=client_id`, and `sub=identity_id`.
- `cmd/iam-server/main.go` — wires `IDTokenService` into the `oauthapp.TokenUseCase`.

## New routes

- `GET /.well-known/openid-configuration` — discovery document (cacheable; lists issuer, endpoints, supported scopes/grants/algs)
- `GET /oauth/userinfo` — returns `{sub, email, email_verified}` for the Bearer principal

## Discovery document highlights

- `response_types_supported`: `["code"]`
- `grant_types_supported`: `["authorization_code", "refresh_token"]`
- `id_token_signing_alg_values_supported`: `["ES256", "RS256"]`
- `code_challenge_methods_supported`: `["S256"]`
- `token_endpoint_auth_methods_supported`: `["client_secret_basic", "client_secret_post", "none"]`

## Notes

- ID token is a JWT signed with the same key as the access token (current active `signing_keys` entry).
- Nonce is required by spec for `id_token` replay prevention; if not provided by the client, the field is omitted from the token.
