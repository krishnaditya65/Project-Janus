# v0.9.0 — Multi-Tenancy: per-tenant policies

Each tenant can now define its own auth policy: password rules, allowed email domains, MFA requirement, max active sessions. Defaults apply when no row exists, so existing tenants are unaffected.

## Migration

`migrations/000006_tenant_policies.up.sql`

- New table `tenant_policies` keyed by `tenant_id` (1:1 with `tenants`). Columns:
  - `password_min_length`, `password_require_upper/digit/symbol`
  - `allowed_email_domains JSONB` (empty array = any)
  - `require_mfa BOOLEAN`
  - `max_active_sessions INT` (0 = unlimited; enforced when session-management API lands)
- `permissions` gets a nullable `tenant_id` FK so each tenant can have its own permissions; `NULL` = system/global permission.
- Replaces the global unique `(name)` on permissions with `(tenant_id, name)` (using `COALESCE(tenant_id::text, '')` in the unique expression so NULL acts as a single bucket).

## Code

- `internal/tenant/domain/policy.go` — `Policy` + `PolicyRepository` interface + `DefaultPolicy()`
- `internal/tenant/infra/postgres/policy_repository.go` — `Get`/`Upsert`; `Get` returns defaults when no row.
- `internal/tenant/app/policy_enforcer.go` — `ValidatePassword`, `ValidateEmailDomain`, with sentinel errors.
- `internal/tenant/transport/http/policy_handler.go` — `GET`/`PUT /tenant/policy`.
- `internal/auth/app/login.go` — fetches policy, returns `ErrMFAEnrollmentRequired` (HTTP 403 `"mfa enrollment required"`) when `require_mfa=true` and the identity has no verified factors.

## New routes

- `GET /tenant/policy` — read the caller-tenant policy (authenticated). Returns defaults when no row.
- `PUT /tenant/policy` — upsert; requires `tenant:update` permission.

## Future work

The migration also adds the column for **tenant-scoped permissions** (`permissions.tenant_id`). The permission bootstrap service still seeds them as global (NULL); flipping individual permissions to tenant-scoped is a follow-up.
