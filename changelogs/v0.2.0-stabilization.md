# v0.2.0 — Stabilization

**Status**: All issues from v0.1.0 resolved; zero new features  
**Date**: 2026-05-30

---

## Summary

No new user-facing features. This release fixes all correctness, security, and code quality issues identified in v0.1.0 before proceeding to the JWT access token phase.

---

## Bug Fixes

### 1. Debug Statements Removed

Three `fmt.Println` calls were left in production code paths.

| File | Removed line |
|---|---|
| `internal/auth/app/login.go` | `fmt.Println("LOGIN HASH:", refreshHash)` |
| `internal/auth/app/refresh.go` | `fmt.Println("REFRESH HASH:", refreshHash)` |
| `internal/session/infra/postgres/repository.go` | `fmt.Println("GET BY REFRESH HASH ERROR:", err)` |

### 2. Hardcoded IP Address Fixed

`sessions.ip_address` was always stored as `"127.0.0.1"`.

- `LoginInput` now carries `IPAddress string` and `UserAgent string`
- Login handler extracts the real client IP with priority: `X-Forwarded-For` → `X-Real-IP` → `RemoteAddr`
- Column remains `text` (not `inet`) — no schema change required
- `RefreshUseCase` already copied `IPAddress` from the old session, so refresh sessions are correct automatically

### 3. Transaction Bypass Bug in UserRoleRepository

`GetRolesForUser` called `r.db.Query(...)` directly, bypassing any active transaction. This meant role lookups during a transactional `CreateUser` operation read from the connection pool rather than the open transaction.

Fixed: now routes through `r.executor(ctx).Query(...)`.

## Security Fixes

### 4. MustPrincipal Panic Eliminated

`authctx.MustPrincipal()` panicked when called without a prior `WithPrincipal`. Two callers were affected:

- `authorization/middleware/authorization.go` → now uses `authctx.Principal()`, returns 401 on missing principal
- `auth/transport/http/me.go` → same

## Code Quality

### 5. Typed Transaction Context Key

`context.WithValue(ctx, "tx", tx)` used a plain string key, which risks silent collision with other packages using the same key.

- Replaced with an unexported `contextKey struct{}` in `internal/platform/postgres/tx/tx.go`
- Added `tx.FromContext(ctx) (pgx.Tx, bool)` so repositories no longer repeat the type assertion

### 6. Shared `Executor` Interface

Every postgres repository defined its own local interface (`executor`, `roleExecutor`, `permissionExecutor`, etc.) with identical method signatures. This is now defined once:

```go
// internal/platform/postgres/tx/tx.go
type Executor interface {
    Exec(ctx context.Context, sql string, args ...any) (pgconn.CommandTag, error)
    QueryRow(ctx context.Context, sql string, args ...any) pgx.Row
    Query(ctx context.Context, sql string, args ...any) (pgx.Rows, error)
}
```

All 9 repositories updated to use `pgtx.Executor` and `pgtx.FromContext(ctx)`:

- `internal/auth/infra/postgres/repository.go`
- `internal/identity/infra/postgres/repository.go`
- `internal/identity/infra/postgresuser/repository.go`
- `internal/tenant/infra/postgres/repository.go`
- `internal/session/infra/postgres/repository.go`
- `internal/authorization/infra/postgres/role_repository.go`
- `internal/authorization/infra/postgres/permission_repository.go`
- `internal/authorization/infra/postgres/user_role_repository.go`
- `internal/authorization/infra/postgres/role_permission_repository.go`

### 7. SlugService Retries Reduced

`GenerateUniqueSlug` previously looped up to 10,000 times with a DB query per iteration. Reduced to 5 attempts with a clear error message on exhaustion.

## New Features

### 8. Logout Endpoint

`POST /logout` — requires authentication, no additional permission.

- `internal/auth/app/logout.go` — `LogoutUseCase` revokes the caller's session by ID; idempotent (already-revoked sessions accepted without error)
- `internal/auth/transport/http/logout.go` — returns `204 No Content`
- Route registered in `main.go`

### 9. CORS Middleware

`httpserver.CORS` middleware added to `internal/platform/httpserver/server.go`. Applied globally via `r.Use(httpserver.CORS)`.

Headers set on every response:
```
Access-Control-Allow-Origin:  *
Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS
Access-Control-Allow-Headers: Content-Type, Authorization, X-Session-ID
Access-Control-Max-Age:       86400
```

OPTIONS preflight requests return `204 No Content` immediately.

> **Note**: `Access-Control-Allow-Origin: *` is intentionally permissive for development. Restrict to specific origins before production deployment.

### 10. Structured Logging (slog)

`log/slog` (stdlib, Go 1.21+) replaces `log.Println`/`log.Fatalf` throughout:

- `cmd/iam-server/main.go` — startup and shutdown events logged as structured JSON to stdout
- `internal/auth/middleware/authentication.go` — auth failures emit `slog.Warn` with `session_id` and `path`; internal errors emit `slog.Error` with `err`

### 11. Input Validation

Register (`POST /register`):
- Email format validated: must contain exactly one `@`, with non-empty local and domain parts, domain containing `.`
- Password minimum length: 8 characters

Login (`POST /login`):
- Email and password must be non-empty

### 12. Consistent JSON Error Responses

New `internal/auth/transport/http/response.go`:

```go
func writeError(w http.ResponseWriter, message string, status int)
func writeJSON(w http.ResponseWriter, v any)
```

All auth transport handlers now return `{"error": "..."}` JSON instead of plain text. Internal error details are no longer leaked to clients (generic `"internal error"` message instead of `err.Error()`).

## Refactoring

### 13. main.go Route Registration Simplified

Repetitive anonymous middleware wrappers replaced with two local helpers:

```go
withAuth := func(next http.Handler) http.Handler { return authMiddleware.Authenticate(next) }
withPerm := func(p string) func(http.Handler) http.Handler { return authorizationmiddleware.RequirePermission(p) }
```

Route block reduced from ~180 lines to ~15 lines with no behavior change.
