# v0.6.0 — MFA (TOTP)

Adds TOTP enrollment and two-step login challenge. When an identity has at least one verified MFA factor, `POST /login` returns `{mfa_required: true, mfa_token}` instead of session/tokens. The client then submits the TOTP code to `POST /mfa/complete` to receive the access/refresh tokens. Backward-compatible: identities without MFA log in unchanged.

## New components

- `internal/mfa/domain/factor.go` — `Factor`, `Repository`
- `internal/mfa/infra/postgres/repository.go` — uses existing `mfa_factors` table
- `internal/mfa/app/challenge_store.go` — Redis-backed `Challenge` with 5-min TTL, GetDel-consumed
- `internal/mfa/app/totp.go` — `TOTPService` (`Enroll`, `VerifyEnrollment`, `Verify`, `Unenroll`, `List`); uses `github.com/pquerna/otp` (SHA1, 6 digits, 30s window, RFC 6238)
- `internal/mfa/app/complete.go` — `CompleteUseCase`: validates challenge + TOTP code, creates session, issues JWT
- `internal/mfa/transport/http/handler.go` — HTTP endpoints

## Changed

- `internal/auth/app/login.go` — after password verify, checks for verified MFA factors. If any exist, generates `mfa_token` (32 bytes random, base64url), stores `Challenge{IdentityID, TenantID, UserID, IPAddress, UserAgent}` in Redis for 5 min, returns `{mfa_required, mfa_token}` (no session, no JWT).
- `LoginOutput` now uses lowercase JSON tags (`access_token`, `session_id`, etc.) for OAuth-style consistency.

## New routes

| Route | Auth | Notes |
|---|---|---|
| `POST /mfa/enroll/totp` | yes | `{label?}` → `{factor_id, secret, qr_url}` |
| `POST /mfa/enroll/verify` | yes | `{factor_id, code}` → 204 marks `verified=true` |
| `GET /mfa/factors` | yes | list user's factors |
| `POST /mfa/complete` | no (uses `mfa_token`) | `{mfa_token, code}` → full login response |

## QR URL format

`otpauth://totp/<issuer>:<email>?secret=<base32>&issuer=<issuer>&algorithm=SHA1&digits=6&period=30`

Compatible with Google Authenticator, Authy, 1Password, Microsoft Authenticator.

## Dependencies added

- `github.com/pquerna/otp` (and indirect `github.com/boombuler/barcode`)

## Notes

- A factor must be **enrolled and verified** before it gates login. An unverified factor is ignored.
- Secret is stored in `mfa_factors.secret_encrypted` as plain base32 today; envelope encryption is part of the post-v0.7.0 Security Hardening roadmap.
